# 2026-10-01: `mix test`

A translated library's Temper tests used to run only through the harness:
`main/0`, then `__temper_tests__/0`, which writes JUnit XML for Temper's
tooling. An Elixir developer reaches for `mix test`, so the output now
supports it too.

A library with tests gets `test/test_helper.exs` (`ExUnit.start()`) and
`test/temper_test.exs`, one ExUnit test per Temper test:

```elixir
test "doubling works" do
  TemperCore.Test.check(&Temper.Tested.doublingWorks__12/1)
end
```

The ExUnit name is the test's own sentence, from TmpL's `rawName`, with
any interpolation already resolved (`"${label} works"` becomes
"doubling works"). It is not the function name, which the harness's
JUnit report keeps. `setup_all` runs the library's top level once, since
tests read module values. `TemperCore.Test.check/1` runs one test through
the same `process` that the harness uses, so soft asserts collect, hard
asserts bail, and a bubble with no failed hard assert reports `Bubble`. It
then raises an `ExUnit.AssertionError` with the messages. The error module
is looked up when the test runs, so temper-core does not depend on ExUnit.

```
  2) test a failing test (Temper.Tested.TemperTest)
     test/temper_test.exs:13
     2 should not double to 5
     nor 3 to 7
...
3 tests, 2 failures
```

The file is text written by the backend, not a tree. `use` and the
`test "..." do` macro are not in the output grammar, and the file is the
same few lines for every library. The test names go through the same
escaping as every string literal.

65 of 65 functional tests still pass. The harness path is unchanged.
