# 2026-10-01: a real app

Entry 25 ran Temper libraries written for other backends. This one runs
be-elixir the other way round: inside a Phoenix app that existed first,
with its own tests and deploy, written in Elixir by hand. The app is
[Marginalia](https://github.com/notactuallytreyanastasio/marginalia), a
LiveView app for reading and revising long-form writing. Its core text
logic now lives in Temper, and Elixir is generated from it. The full case
study is
[marginalia#6](https://github.com/notactuallytreyanastasio/marginalia/pull/6);
this entry covers what it taught the backend.

| Temper source | Replaces | What it does |
|---|---|---|
| `diff.temper.md` | `Marginalia.Diff` | paragraph diff of two drafts (LCS) |
| `words.temper.md` | `Marginalia.Rewrite.diff/2` | word diff, a port of `List.myers_difference/2` |
| `blocks.temper.md` | `Marginalia.Reading.split/1` | a draft's blocks, fenced code kept whole |
| `sentences.temper.md` | `Marginalia.Works.Sentences` | one sentence per line, prose only |
| `reflow.temper.md` | `Marginalia.Works.Reflow` | paragraphs recovered from `pdftotext` output |
| `segmenter.temper.md` | `Marginalia.Works.Segmenter` | a manuscript split into sections |

Each Elixir module stayed, as a facade with its old API over the generated
`Temper.MarginaliaCore`. No caller changed, and all 1,158 of the app's
tests run against the generated code.

## The build

The generated Elixir is committed. Building, testing and deploying the app
needs no JVM and no Temper; only regenerating does.

```elixir
# mix.exs
{:temper_marginalia_core, path: "temper/out/marginalia-core"},
...
"temper.gen": ["cmd bin/temper-gen"],
"temper.check": ["cmd bin/temper-gen --check"],
precommit: ["temper.check", "compile --warnings-as-errors", ...]
```

`bin/temper-gen` builds `temper/*/` in a scratch directory with
`temper build -b elixir`, drops the source maps, and replaces `temper/out`.
`temper/out/TEMPER_COMMIT` records the temper-blimp commit that built it.
`--check` builds again and fails if anything differs by a byte. That check
is only possible because of two earlier chapters: the output is
deterministic, and it compiles without warnings (entry 23), so
`--warnings-as-errors` passes over it. The Dockerfile copies `temper/out`
in before `mix deps.get`, and the release carries it like any path
dependency.

## What the app needed from the backend

- **Self-init (entry 24).** A LiveView calls `Temper.MarginaliaCore.diff/2`
  cold, from whatever process it is in.
- **`@imu` classes as structs (entry 18).** `Row`, `Part` and `Section`
  come back as plain structs, so the facades pattern-match on them.
- **`@connected` in the library's own `_connected.ex`.** Temper's core
  strings carry no Unicode character data, and the originals asked
  Unicode questions: `\s`, `\p{Lu}`, `\p{L}`, `\p{N}` under PCRE's `u`
  flag, case mapping, and grapheme counts. Each is a one-line `@connected`
  declaration, answered by the same engine the original code used, so
  each is exact by construction. Every decision stays in Temper.
- **Constant-time lists (entry 17).** The LCS table is a flat list indexed
  `i * width + j`.

## What it cost, and the two cheap fixes

Timed against the Elixir each port replaced, the first numbers were 3x to
5x slower. Measuring found two causes.

**An exported helper pays the entry on every call.** Every exported
function runs `__temper_init__()` and `TemperCore.Heap.entry` (entry 18). I
had exported small helpers like `isRegexSpace`, which run once per
character, so each character paid for the entry. Only the functions the
facades call are exported now. A Temper library meant for Elixir should
export its API and nothing else.

**A host predicate asked PCRE about every character.** ASCII is answered
directly now (`def isUnicodeSpace(cp) when cp < 128`), checked against PCRE
on all 128 code points.

```
                                              Elixir    Temper   ratio
word diff, 2,000-word section, 4% edited        4 ms     14 ms   3.5x
paragraph diff, 60 paragraphs                   8 ms     22 ms   2.7x
sentences reflow, 5,400 words                   2 ms      8 ms   3.5x
PDF page reflow, 400 lines                     11 ms      3 ms   0.3x
segmenter, 11,700-word manuscript              20 ms     68 ms   3.4x
```

What remains is mostly walking strings one code point at a time where the
originals matched regexes over whole binaries. Two changes would close it:
a cheaper entry for calls inside a library, and better string primitives
in Temper itself.

## Equivalent, checked against the original

Each port had to give the same output as the original on every input.
`temper/verify/` in the app keeps the original modules, and a harness per
port runs old and new on random inputs and stops at the first difference.
Over the port they agreed on more than 90,000 inputs: word and paragraph
diffs, documents, PDF pages, and manuscripts of up to 12,000 words.

Porting faithfully found a bug. The segmenter's marker regex was meant to
match three or more em dashes, `—{3,}`. With no `u` flag, PCRE repeats only
the em dash's last byte, a sequence valid UTF-8 never contains, so a row of
em dashes was never a section break. The port reproduced the bug in one
commit and fixed it, with a test, in the next.
